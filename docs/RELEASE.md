# إنشاء مفتاح توقيع جديد لـ IdeaBridge (مرة واحدة)

> هذا لمن لا يملك مفتاحًا سابقًا. المفتاح يُنشأ على جهازك أنت، وكلمتا المرور تختارهما بنفسك ولا تُرسلان لأحد.

1. ثبّت Java (JDK 17) على حاسوبك، أو على الهاتف عبر Termux: `pkg update && pkg install openjdk-17`.
2. شغّل:

       keytool -genkeypair -v -keystore ideabridge.jks -alias ideabridge -keyalg RSA -keysize 2048 -validity 10000

   اختر كلمة مرور قوية، وأجب عن الأسئلة بأي قيم، وعند سؤال كلمة مرور المفتاح اضغط Enter لاستعمال الكلمة نفسها.
3. اعرف بصمة المفتاح (اختياري، للمقارنة لاحقًا):

       keytool -list -v -keystore ideabridge.jks -alias ideabridge

4. **احفظ `ideabridge.jks` وكلمتي المرور في مكانين على الأقل.** إن ضاع الملف فلا يمكن تحديث التطبيق بالاسم نفسه أبدًا.
   لا تضع الملف داخل المستودع (`.gitignore` يمنع `*.jks`).
5. ثم تابع من القسم التالي (الأسرار الأربعة)، وقيمها: alias = `ideabridge`، وكلمة مرور المفتاح = كلمة مرور الملف إن ضغطت Enter.

# إصدار موقّع بمفتاحك السابق

لا يحتوي المستودع على أي مفتاح أو كلمة مرور، ولم يُنشأ مفتاح جديد. التوقيع يتم على GitHub فقط من أسرارك.

## 1) جهّز الأسرار (مرة واحدة)
على جهازك، في مجلد فيه ملف مفتاحك القديم (مثلًا `my-old-key.jks`):

    base64 -w0 my-old-key.jks      # على ماك: base64 -i my-old-key.jks | tr -d '\n'

ثم في GitHub: Settings → Secrets and variables → Actions → New repository secret، وأنشئ:

| اسم السر | القيمة |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | ناتج الأمر أعلاه |
| `ANDROID_KEYSTORE_PASSWORD` | كلمة مرور ملف المفتاح |
| `ANDROID_KEY_ALIAS` | اسم المفتاح (alias) |
| `ANDROID_KEY_PASSWORD` | كلمة مرور المفتاح |

لا ترسل هذه القيم في أي محادثة ولا تضعها في ملفات المشروع.

## 2) اعرف بصمة مفتاحك القديم

    keytool -list -v -keystore my-old-key.jks -alias YOUR_ALIAS

انسخ سطر `SHA256:` فقط (البصمة معلومة عامة وليست سرًا).

بعد أول بناء ناجح يطبع السجل سطر `Actual SHA-256`. احفظه كمتغير مستودع باسم `EXPECTED_SHA256`
(Settings → Secrets and variables → Actions → تبويب Variables). من بعدها يفشل السير برسالة MISMATCH
إن وُقّع أي إصدار لاحق بمفتاح مختلف، فلا يُسلَّم APK يُظنّ أنه تحديث وهو ليس كذلك.

## 3) ابنِ الإصدار
Actions → «Build signed release APK» → Run workflow. في آخر خطوات السجل تظهر بصمة SHA-256 للـ APK.
**إذا تطابقت مع بصمة مفتاحك القديم فالتوقيع صحيح** ويمكن تثبيته كتحديث فوق نسخة وُقّعت بالمفتاح نفسه.

## تنبيهات
- النسخ التجريبية الحالية موقّعة بمفتاح debug؛ لا يمكن تحديثها بالإصدار الموقّع. قبل تثبيته **صدّر نسخة احتياطية من الإعدادات**، ثم احذف النسخة التجريبية وثبّت الإصدار الموقّع واستورد النسخة.
- رقم الإصدار (`versionCode`) يساوي رقم تشغيل GitHub، فيزيد تلقائيًا.
